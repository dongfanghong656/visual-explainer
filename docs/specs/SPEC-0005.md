# SPEC-0005 — Local Codex dual-MCP discovery and activation

- Status: IMPLEMENTED_LOCAL_CLI_VERIFIED
- Package: `0.11.0-alpha.1` post-release repair
- Requirement: REQ-0008
- Scope: local Codex host only

## Activation model

```text
Skill trigger phrases
  -> agents/openai.yaml MCP dependency
  -> active Codex config server entry
  -> fresh task exposes the MCP tool
  -> agent calls the tool when the visual/task-proof boundary applies
```

The general renderer and Task Proof are separate stdio servers and must both be present:

- `visual-explainer` exposes three preparation/rendering tools;
- `visual-explainer-task-proof` exposes eight evidence and review tools.

## Invariants

1. Skill presence alone is not treated as MCP exposure.
2. MCP configuration alone is not treated as a successful live call.
3. Both Skill dependency declarations use the same server names as the active Codex configuration.
4. Release and CI verification call both servers rather than inferring the general renderer from Task Proof.
5. Existing Codex processes are not claimed to hot-reload configuration; restart and a new task are the activation boundary.
6. Routine code edits and short prose remain outside automatic visual rendering.

## Boundary

This specification does not implement ChatGPT web connectors, remote HTTP MCP transport, autonomous visualization of every response, or stable-release promotion.
