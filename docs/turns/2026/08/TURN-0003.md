## User intent

Continue adversarial review and improve the Skill/MCP so an implementation AI cannot declare a task complete by selecting an incomplete acceptance set, laundering evidence, inventing a reviewer level, replaying an authority receipt, or supplying a bare passing status.

## Changes

- upgraded the frozen contract runtime to protocol `2.4.0`;
- added source requirements, source-use completeness, and symmetric criterion mapping;
- froze named-check policy, executable, argument, working-directory, result, reviewer, and Claim-HEAD identity;
- bound Claim identity to contract, criteria, repository, base, and chronology;
- required one trusted-adapter authority receipt for every declared source;
- bound Review identity, procedure, Claim digest, contract, receipt set, exact repository scope, and chronology;
- replaced caller-trusted evidence/lifecycle status strings with verifier-bound assessment objects;
- distinguished hard tampering failures from missing-evidence inconclusive results;
- added strict schema, example, current specification, and adversarial/static tests;
- marked protocols 2.1 and 2.3 as superseded rather than leaving multiple active authorities.

## Evidence boundary

The repository strict test runner discovers all new `*.test.mjs` files. Remote Linux Node 20/22 CI and final HEAD readback are still required. This turn does not yet integrate contract enforcement into all public MCP and Skill entrypoints.

## Decisions

- claimant-provisional contracts can never yield final `PASS`;
- a textual authority level or assurance label cannot authorize acceptance;
- the final reviewer must revalidate every authority source through trusted adapters;
- same-name checks are identified by content-bound policy and verified receipts, not names alone;
- bare caller-supplied `PASS` values cannot authorize evidence or lifecycle gates;
- explicit exclusions and deferrals remain visible and cap source coverage.

## Risks

- trusted external adapters are not yet implemented;
- requirement extraction from unstructured sources can still omit requirements before they enter the contract;
- public Author/Reviewer entrypoints are not yet contract-mandatory;
- reviewer identity remains procedural unless cryptographic or platform attestation is added.

## Next action

Verify the exact staging HEAD in draft PR #3, then implement mandatory contract enforcement in public MCP/Skill paths without weakening the strict core.
