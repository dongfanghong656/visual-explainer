# REQ-0003 — Causal change-logic visualization

- Status: ACCEPTED
- Priority: P0
- Source: user request and supplied scroll-restoration sequence example
- Dependencies: REQ-0001

## Statement

The visual shall explain the project change as a causal mechanism rather than a file list. It must show responsibilities, event order, state ownership, writes, invalidation, user/error interruption, invariants, termination, evidence, and remaining work in a readable one-page or scrollable report.

## Acceptance criteria

1. Actors represent stable responsibilities or state owners rather than arbitrary files.
2. Every arrow is labeled as an event, state transition, read/write, cancellation, or verification action.
3. The bundle supports before/change/after/interrupt/verification phases, preconditions, effects, invariants, and termination.
4. The primary diagram remains readable; any actors/events omitted by density limits are explicitly disclosed and all events remain in a complete registry.
5. Author claim semantics are amber; independently verified event overlays are green, contradictions red, unsupported/blocked plum, and unassessed gray.
6. The page includes task lanes, acceptance tables, evidence registry, risks, and unknowns.
7. Untrusted text is escaped and no hidden JavaScript is required for the deterministic Task Proof page.
