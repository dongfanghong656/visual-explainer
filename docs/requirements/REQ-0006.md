# REQ-0006 — Single strict runtime and reproducible evidence identity

- Status: ACCEPTED
- Priority: P0
- Source: adversarial review of the Task Proof alpha
- Dependencies: REQ-0001 through REQ-0005

## Statement

Task Proof shall have one canonical validator, snapshot model, receipt model, gate calculator, artifact writer, renderer, and MCP surface. Compatibility entrypoints may delegate to the strict runtime but may not retain weaker parallel semantics. Repository and evidence identity must bind immutable content rather than clone paths, display-only metadata, or mutable references.

## Acceptance criteria

1. Every public completion/review path delegates to the same strict runtime.
2. Dirty snapshots bind index and working-tree bytes, symlink targets, gitlinks, and exact evidence files.
3. Receipt identity binds evidence semantics, criterion/claim support, producer/reviewer run, snapshot, result, and locator.
4. Legacy protocols are explicitly superseded and cannot be rediscovered as current authorities.
5. Source-integrity tests fail on duplicate active runtimes, obsolete imports, or stale tool registrations.

## Current state

The strict runtime and source identity core exist. Full public-entrypoint convergence remains part of TASK-0007.
